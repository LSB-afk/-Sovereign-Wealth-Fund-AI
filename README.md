# 근거 기반 Peer Group 분석 에이전트 (KIC AI 에이전트 공모전 MVP)

분석 대상 기업(NVIDIA, AMD)과 분석 기준일을 고르면, 에이전트가 공개 공시(SEC EDGAR)를 조회해 비교기업(Peer)을 제안합니다. 선정·제외 근거, 재무 비교, 출처를 함께 보여 줍니다. 주가 예측이나 매매 기능은 범위에 없습니다.

## 실행

```bash
npm install
npm run build && npm start        # http://localhost:3000  (개발: npm run dev)
npm test                          # 핵심 로직 검증 (15개)
```

- **데모 모드**는 API 키 없이 실행됩니다. 저장된 EDGAR 스냅샷(`data/snapshot/`)과 공개된 규칙 기반 정책을 사용하며 LLM은 쓰지 않습니다. 화면과 보고서에 데모 모드라고 표시됩니다.
- **실제 모드**는 `.env.local`에 `ANTHROPIC_API_KEY`와 `SEC_USER_AGENT`가 있어야 켜집니다(`.env.example` 참고). EDGAR를 실시간으로 조회하고 Claude가 도구 호출을 결정합니다. 실패해도 데모 결과로 대체하지 않으며, 부분 결과와 실패 이유를 반환합니다.

### 데모 재현
1. `npm run build && npm start`를 실행합니다.
2. NVDA 또는 AMD를 고르고, 기준일(기본값은 스냅샷 수집일)을 정한 뒤 **Peer 분석 시작**을 누릅니다.
3. 결과를 확인합니다: 선정 Peer와 근거, 후보별 판단표, 제외 이유, 사업구조 비교, 재무 비교표, 유의사항, 출처 목록. 출처 칩 `S#`를 누르면 출처 목록으로 이동하고, 거기서 원문 링크와 수집한 발췌를 볼 수 있습니다.
4. 판단표의 Peer 체크박스나 카드의 "제외"로 Peer를 바꾸면 변경 배너가 뜨고 비교표·중앙값·다운로드가 갱신됩니다.
5. Markdown 보고서와 CSV(값별 출처 URL·공시일·접수번호 포함)를 내려받습니다.
6. 기준일을 `2025-06-30`으로 바꾸면 그 이후 공시가 빠지고 전년도 연간 자료가 쓰입니다.

스냅샷 갱신: `SEC_USER_AGENT="Org Name you@example.com" npm run snapshot`

## 구조

| 파일 | 역할 |
|---|---|
| `lib/edgar.ts` | SEC EDGAR 공식 API(companyfacts, submissions, Archives 원문) 조회, 원문 발췌 |
| `lib/datasource.ts` | 데이터 소스 교체 지점: `liveSource`(실시간) / `snapshotSource`(데모) |
| `lib/financials.ts` | XBRL 사실값 → 정규화 지표. 모든 숫자 계산 담당 |
| `lib/peer.ts` | 비교 가능성 검사, 규칙 기반 참고 점수(가중치 공개) |
| `lib/agent.ts` | 도구 정의, 출처 레지스트리, 한도가 있는 에이전트 루프, 데모용 `RulePolicy` |
| `lib/llm.ts` | LLM 교체 지점: `LlmPolicy`(Claude, 수동 tool-use 루프) |
| `lib/report.ts` | 비교표·Markdown·CSV (클라이언트에서 Peer 변경 시 재계산) |
| `app/` | Next.js 화면과 `/api/analyze` (NDJSON 스트리밍 진행 상태) |
| `data/companies.json` | 후보군, 큐레이션 프로필(정성 정보만) |
| `data/snapshot/` | 데모용 EDGAR 스냅샷(수집 시각은 `meta.json`) |

### 에이전트 도구
`list_candidates`, `get_company_profile`, `search_filings`, `get_filing_excerpt`(경쟁/고객/사업부문), `get_financials`, `check_comparability`, `save_review`.

한도(`DEFAULT_LIMITS`):
- 실제 모드: 도구 호출 60회, 판단 단계 20회, 재시도 2회, 280초.
- 데모 모드: 도구 호출 70회, 판단 단계 12회, 재시도 2회, 60초.

일시적 오류(네트워크·5xx)만 재시도하고, 입력 오류는 재시도하지 않습니다. 한도를 넘거나 LLM 호출이 실패하면 `partial`/`failed` 상태와 이유를 반환합니다.

데모 정책의 분기: 사업 유사성이 '부분 유사'이고 대상의 10-K 경쟁사 기술에 이름이 없는 후보는, 그 후보의 10-K 경쟁 섹션을 추가로 조회한 뒤 다시 평가합니다.

## 차별화 기능

### 1. Peer 강건성 테스트 (`lib/robustness.ts`, 탭 "강건성")
- 다섯 기준의 가중치를 균등 분포(디리클레)에서 2,000번 뽑습니다. 선정 기준선도 0.40~0.50 사이에서 함께 바꿉니다.
- 매번 같은 선정 규칙을 다시 적용해 후보별 선정 빈도를 계산합니다.
- 결과는 강건(80% 이상), 대체로 선정, 경계선, 거의 제외로 나눠 보여 주고, 지도 노드에도 % 배지로 표시합니다.
- 시드를 고정해 결과를 재현할 수 있습니다. "점수가 임의적이지 않냐"는 질문에 숫자로 답하기 위한 기능입니다.

### 2. 시점 비교 (`lib/timeline.ts`, `/api/timeline`, 탭 "시점 비교")
- 기준일로부터 3년 전, 2년 전, 1년 전, 당일 네 시점에서 같은 에이전트를 다시 실행합니다.
- 각 시점은 그날까지 공시된 자료만 씁니다(미래 정보 누수 없음).
- Peer 편입·제외 변화를 표로 보여 주고, 바뀐 칸은 주황 테두리로 강조합니다. 변화 요약도 코드가 생성합니다.
- 스냅샷에는 기업별 최근 4개 연간보고서의 원문 발췌만 있어, 그보다 오래된 시점에는 원문 근거가 빠질 수 있습니다.

### 3. 공시 기반 지식그래프 (`lib/graph.ts`, `/api/graph`, 탭 "지식그래프")
- 노드: 기업, 외부 기업, 판매 시장. 관계: 경쟁사로 기재, 공급, 고객, 협력, 판매 시장, 제품군.
- 데모 모드는 규칙으로 추출합니다. 10-K 경쟁 섹션에서 다른 기업명이 나온 문장을 근거 인용으로 저장합니다.
- 실제 모드는 Claude가 원문 발췌에서 관계를 제안하고(structured output), 코드가 검증합니다. **인용문이 원문에 글자 그대로 있고 관계 종류가 허용 목록에 있을 때만** 채택하고, 나머지는 '원문 대조 탈락'으로 셉니다.
- 모든 관계는 공시 URL과 원문 인용을 함께 가집니다. 제품·시장 관계는 '큐레이션'으로 표시합니다.
- 화살표 A → B는 A의 연간보고서가 B를 그 관계로 기재했다는 뜻입니다. 원 크기는 다른 기업 보고서에서 경쟁사로 지목된 횟수입니다.
- 데모 스냅샷 기준: 연간보고서 11건, 경쟁 관계 21건. 예: Intel 10-K는 파운드리 사업 때문에 TSMC를 경쟁사로 기재합니다.

## 데이터와 계산 규칙

- **출처:** SEC EDGAR의 us-gaap XBRL 값만 씁니다. 조건은 USD, 연간 양식(10-K, 10-K/A, 10-KT, 20-F, 20-F/A), 차원 없음(연결 합계)입니다.
  - 매출: `Revenues` → `RevenueFromContractWithCustomerExcludingAssessedTax` → `SalesRevenueNet` 순서로 찾고, 당기와 전기를 모두 가진 항목을 우선합니다.
  - 영업이익: `OperatingIncomeLoss`.
  - R&D: `ResearchAndDevelopmentExpense`.
- **연간 판정:** 기간이 350–380일인 값만 연간으로 봅니다(52/53주 회계연도 포함). 10-K 안의 분기 값은 제외합니다.
- **기준일:** `filed <= 기준일`인 값만 씁니다. 원문 발췌와 공시 목록도 같은 규칙을 따릅니다.
- **중복·수정 공시:** 같은 기간 값이 여러 공시에 있으면 기준일 이전의 가장 최근 공시 값을 씁니다. 공시일이 같으면 수정 공시(/A)를 우선하고, 값이 다르면 유의사항에 기록합니다. 원문 발췌에는 원 공시를 씁니다(수정 공시는 보통 Part III/첨부만 담기 때문).
- **누락:** 값이 없으면 `누락`으로 표시하고 추정하지 않습니다. TSMC처럼 IFRS 데이터만 있는 기업은 재무 비교 불가(차단)로 자동 제외되며, 선정으로 저장하는 것도 코드가 막습니다.
- **값별 보존 정보:** 티커, CIK, 지표 정의, XBRL 항목명, 값, 단위, 회계기간, 양식, 공시일, 접수번호, 원문 URL, 수집 시각.
- **출처 링크:** 도구가 실제로 수집한 자료로 출처 레지스트리(`S#`)를 만듭니다. LLM이 쓴 출처 ID가 레지스트리에 없으면 제거하고 경고를 남깁니다.
- **숫자 검증:** LLM이 쓴 근거 문장에서 퍼센트, `$xB`, `x배` 숫자를 찾아 도구 결과와 대조하고, 일치하지 않으면 경고합니다.
- **참고 점수:** 초기 설정입니다. 가중치는 제품·사업모델 35%, 고객·시장 20%, 규모 15%, 성장·수익성 15%, 자료 충분성 15%이며, 정답이나 확률이 아닙니다. 산식은 화면과 보고서에 공개합니다.

데이터 이용 조건: SEC EDGAR는 공개 데이터이며, SEC 공정접근 정책(초당 10회 이하, 연락처가 담긴 User-Agent)을 따라야 합니다.

## 알려진 한계

- 기업 프로필(제품·시장 태그)은 사람이 정리한 정성 요약입니다. 세그먼트별 매출 수치는 수집하지 않습니다(companyfacts API에 차원 데이터가 없음).
- 원문 발췌는 키워드 기반입니다. 섹션 경계를 정확히 잘라 내지 못할 수 있습니다.
- 회계연도 종료월이 다른 기업(NVDA 1월, AVGO 11월 등)을 같은 '최근 연간'으로 비교합니다. 차이는 유의사항에 표시합니다.
- 후보군은 고정 목록 10개, 분석 대상은 NVDA·AMD 2개입니다. 데모 판단은 규칙 기반이라 LLM 판단과 다를 수 있습니다.
- 실시간 조회 캐시는 프로세스 메모리에만 있습니다.
